═══════════════════════════════════════════════════════════════════
Remote access
═══════════════════════════════════════════════════════════════════

The gateway is published at https://{{ include "openshell-driver-kyma.gatewayIngressHost" . }}
and authenticates every call with OIDC. Register it once with the openshell CLI
(a browser opens for login):

  openshell gateway add https://{{ include "openshell-driver-kyma.gatewayIngressHost" . }} --name kyma \
    --oidc-issuer {{ .Values.gateway.oidc.issuer }} \
    --oidc-client-id {{ .Values.gateway.oidc.clientId }} \
    --oidc-audience {{ .Values.gateway.oidc.audience }}
{{- if eq .Values.gatewayIngress.policyAction "DENY" }}

If that host answers `403 RBAC: access denied` to everyone, the ingress gateway
already allowlists per host: set gatewayIngress.policyAction=ALLOW (see the
value's comment before you do).
{{- end }}

{{- if .Values.inferenceProvider.enabled }}

═══════════════════════════════════════════════════════════════════
Inference provider
═══════════════════════════════════════════════════════════════════

The post-install hook registers a provider profile and creates a provider
on the in-pod gateway:

  profile:  {{ include "openshell-driver-kyma.inferenceProfileId" . }}
  provider: {{ include "openshell-driver-kyma.inferenceProviderName" . }}

Attach the provider when you create a sandbox:

  openshell sandbox create --provider {{ include "openshell-driver-kyma.inferenceProviderName" . }} ...

The sandbox then has ANTHROPIC_BASE_URL and ANTHROPIC_MODEL in its
environment, and its supervisor injects the API key into requests to
the endpoint of `inferenceProvider.baseUrl`.
{{- end }}
{{- if .Values.bedrockBridge.enabled }}

═══════════════════════════════════════════════════════════════════
SAP AI Core translation bridge is deployed.
═══════════════════════════════════════════════════════════════════

The bridge speaks the Anthropic Messages API on the inside
(`POST /v1/messages`) and translates outbound to SAP AI Core's
deployed Bedrock InvokeModel endpoints. Sandbox pods do NOT need
Bedrock-mode env or AWS creds: the bridge is a normal Anthropic
endpoint. The provider profile names its host and port, sandboxes are
created with `--provider <name>`, and the sandbox's supervisor injects
the provider's credential into requests to it. With networkPolicy.enabled,
the bridge admits only OpenShell pods in the release namespace, so sandboxes
elsewhere (managed or operator mode, or a `namespace` other than the release
namespace) cannot reach it.

In-cluster bridge URL:
  http://{{ include "openshell-driver-kyma.bedrockBridgeFullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:8787

To wire claude-code through it: set the chart's
`inferenceProvider.baseUrl` to that URL and `inferenceProvider.type`
to `anthropic` (the bridge is a normal Anthropic upstream from the
sandbox's POV — `x-api-key` is accepted and ignored, since SAP auth
is XSUAA-bearer-side, on the bridge):

  inferenceProvider:
    enabled: true
    type: anthropic
    baseUrl: http://{{ include "openshell-driver-kyma.bedrockBridgeFullname" . }}.{{ .Release.Namespace }}.svc.cluster.local:8787
    modelId: <a key from your bedrockBridge.modelMap>
    credentialSecret:
      name: <a Secret you pre-created>
      key: api-key   # any non-empty value; bridge ignores it

Verify the bridge is healthy:
  kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "openshell-driver-kyma.bedrockBridgeFullname" . }} 8787:8787 &
  curl -fsS http://localhost:8787/healthz -i | head -3

Tail bridge logs while a sandbox is running to confirm traffic:
  kubectl -n {{ .Release.Namespace }} logs deploy/{{ include "openshell-driver-kyma.bedrockBridgeFullname" . }} -f
{{- end }}
