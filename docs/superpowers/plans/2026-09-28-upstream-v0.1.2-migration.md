# Upstream v0.1.2 Migration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `openshell-driver-kyma` onto upstream OpenShell v0.1.2 by adopting the schema-v2 gateway config and implementing driver-side sandbox authentication, then lift the `GATEWAY_REF` pin.

**Architecture:** v0.1.2 deletes the gateway's own Kubernetes ServiceAccount bootstrap authenticator and delegates it to the compute driver over a new `AuthenticateSandbox` RPC. This driver implements that RPC by doing the TokenReview the gateway used to do, returns a stable `runtime_identity` from create/start/authenticate so the gateway's binding check passes, and acknowledges the resource-admission policy the chart configures. The chart moves its gateway TOML to schema v2.

**Tech Stack:** Rust (tonic/prost gRPC, kube-rs), Helm, Kubernetes (`agents.x-k8s.io` Sandbox CRs), Docker-based dev container.

**Spec:** `docs/superpowers/specs/2026-09-28-upstream-v0.1.2-migration-design.md`

## Global Constraints

- **Base branch:** all work happens on top of `origin/upstream-sync/v0.1.2-36405676769` (PR #70), which already re-vendors the v0.1.2 proto and adds the declining `AuthenticateSandbox` stub this plan replaces. Do **not** branch from `main` — `main` has the v0.0.116 proto and none of this will compile.
- **This lands as one coordinated change.** A v0.1.2 gateway with an old driver cannot bootstrap sandboxes; a v0.0.116 gateway rejects a schema-v2 config. There is no supported mixed state, so the pin lift (Task 9) ships in the same PR as the driver and chart work. Do not merge intermediate tasks to `main` on their own.
- **Rust builds and tests run inside the dev container only** — the host has no Rust toolchain. Use `make test` (which is `fmt-check` + `clippy` + `cargo test --workspace --lib --tests` inside the container). Never run bare `cargo` on the host.
- **Commit identity:** `st-gr <38470677+st-gr@users.noreply.github.com>`. The host git config is already correct — pass **no** `-c user.email` or `-c user.name`.
- **Sandbox token audience is `openshell-gateway`** — already this driver's `SA_TOKEN_AUDIENCE` (`provisioner.rs:97`) and upstream's `SANDBOX_TOKEN_AUDIENCE` (`driver.rs:347`). Do not introduce a second constant.

- **Never log credential values.** The `credential` field is marked `[(openshell.options.v1.secret) = true]` in the proto.
- **`provisioner.rs` is 4641 lines and `driver.rs` is 875.** Both are far over this repo's ~300-line preference. New logic goes in the new `sandbox_auth.rs` module rather than growing either further. Do not refactor the existing files as a side effect.
- **Do not touch `inference.local` / `provider_profile_sources`.** Explicitly sequenced as separate work after this migration.
- **Already correct on the base branch — do not redo.** PR #70 populates `resource_capabilities` (CPU/memory limits, GPU default and count selection), `driver_reports_runtime_readiness: false`, `rootfs_tar_staging_dir`/`rootfs_tar_max_bytes`, and the `extension` `PeerMetadata` block. Only `supports_sandbox_authentication` and `resource_admission_policy` are wrong there, and Tasks 4 and 5 fix exactly those two.
- **Known gap, deliberately not closed here.** When `driver_config_allow_volumes` is true this driver attaches caller-supplied volumes without consulting the admission policy, where every upstream driver calls `admit(...)` on them first. The flag defaults to `false`, so no deployment is affected. Do not enable it as part of this work, and do not build the evaluator — it is recorded in the spec as follow-up.

## Review Focus

Input classes the spec implies that the happy-path tests would miss. Each has a test assigned to the task that owns the code.

1. **A token authenticated for the right SA name but in a namespace this driver does not serve** — must be `permission_denied`, not accepted. Cross-namespace SA names collide freely in Kubernetes. (Task 3)
2. **A pod carrying the sandbox-id label but owned by a different Sandbox CR** — label values are not a trust boundary; ownership must be verified, and a mismatch must be `permission_denied`. (Task 3)
3. **A credential valid for a sandbox that has since been deleted** — must be `permission_denied` with no panic and no `internal`, since this is a normal race, not a server fault. (Task 3)
4. **TokenReview itself failing with 403 because the RBAC move was missed** — must surface as `internal`/`unavailable` and be distinguishable in logs from a rejected credential, or a misconfigured deployment looks like an attack. (Task 3)
5. **An empty or whitespace-only credential** — must be rejected before any apiserver call, as `unauthenticated`. (Task 2)

### Task 1: Runtime identity — derive it and return it from create and start

The gateway records the identity a driver reports at create time and compares it on every bootstrap. If `supports_sandbox_authentication` is true and `CreateSandbox` returns an empty string, the gateway raises "compute driver did not return a runtime identity" and **compensates the create, deleting the sandbox**. So this lands before the capability is flipped.

**Design decision (made here, rationale for the reviewer):** upstream encodes `kubernetes://{namespace}/{cr_uid}/{pod_uid}` and stashes the pod UID in a CR annotation so it can be recovered later. This driver uses `kyma://{namespace}/{sandbox_cr_uid}` — **no pod UID**. Two reasons: this driver creates a Sandbox CR and the agent-sandbox controller creates the pod afterwards, so no pod UID exists at `CreateSandbox` time without adding a wait; and the CR outlives pod replacement, so a CR-scoped identity stays valid across restarts where a pod-scoped one would go stale. The security property upstream gets from the pod UID is preserved in Task 3, which validates pod ownership against the CR on every authentication.

```rust
/// URI scheme for this driver's runtime identities.
///
/// Upstream's Kubernetes driver uses `kubernetes://{ns}/{cr_uid}/{pod_uid}`.
/// This driver omits the pod UID: the Sandbox CR is created here but its Pod is
/// created afterwards by the agent-sandbox controller, so no Pod UID exists at
/// `CreateSandbox` time, and the CR outlives Pod replacement. Pod-level binding
/// is enforced instead at authentication time, by checking that the presenting
/// Pod is owned by this CR.
pub const RUNTIME_IDENTITY_SCHEME: &str = "kyma";

/// Opaque, stable identity of the compute resource backing a sandbox.
///
/// The gateway persists the value returned by `CreateSandbox`/`StartSandbox`
/// and compares it byte-for-byte with the value `AuthenticateSandbox` returns.
/// Every producer must go through this function so the three can never drift.
#[must_use]
pub fn runtime_identity(namespace: &str, sandbox_uid: &str) -> String {
    format!("{RUNTIME_IDENTITY_SCHEME}://{namespace}/{sandbox_uid}")
}
```

```rust
use crate::error::DriverError;
use k8s_openapi::api::authentication::v1::{TokenReviewStatus, UserInfo};

/// Audience this driver projects onto sandbox ServiceAccount tokens and
/// requires back from TokenReview. Matches upstream's `SANDBOX_TOKEN_AUDIENCE`.
pub use crate::provisioner::SA_TOKEN_AUDIENCE;

/// Kubernetes-populated TokenReview extras identifying the presenting Pod.
pub const POD_NAME_EXTRA: &str = "authentication.kubernetes.io/pod-name";
pub const POD_UID_EXTRA: &str = "authentication.kubernetes.io/pod-uid";

const SA_USERNAME_PREFIX: &str = "system:serviceaccount:";

/// The Pod identity a verified sandbox credential resolves to.
#[derive(Debug, Clone, PartialEq, Eq)]
pub struct TokenIdentity {
    pub namespace: String,
    pub pod_name: String,
    pub pod_uid: String,
}

/// Reject an empty credential before spending an apiserver round trip on it.
pub fn reject_blank_credential(credential: &str) -> Result<(), DriverError> {
    if credential.trim().is_empty() {
        return Err(DriverError::Unauthenticated(
            "sandbox credential was empty".to_string(),
        ));
    }
    Ok(())
}

fn user_extra_one(user: &UserInfo, key: &str) -> Result<String, DriverError> {
    user.extra
        .as_ref()
        .and_then(|extra| extra.get(key))
        .and_then(|values| match values.as_slice() {
            [single] => Some(single.clone()),
            _ => None,
        })
        .ok_or_else(|| {
            DriverError::PermissionDenied(format!(
                "sandbox credential is missing exactly one {key}"
            ))
        })
}

/// Validate a TokenReview result and extract the presenting Pod's identity.
///
/// `Ok(None)` means the apiserver did not authenticate the token at all, which
/// the caller reports as a plain rejection. `Err` means the token authenticated
/// but is not one this driver accepts.
pub fn token_review_identity(
    status: &TokenReviewStatus,
    expected_service_account: &str,
) -> Result<Option<TokenIdentity>, DriverError> {
    if status.authenticated != Some(true) {
        return Ok(None);
    }
    if !status
        .audiences
        .as_deref()
        .unwrap_or_default()
        .iter()
        .any(|audience| audience == SA_TOKEN_AUDIENCE)
    {
        return Err(DriverError::Unauthenticated(
            "sandbox credential audience not accepted".to_string(),
        ));
    }
    let user = status.user.as_ref().ok_or_else(|| {
        DriverError::PermissionDenied("TokenReview returned no user".to_string())
    })?;
    let (namespace, service_account) = user
        .username
        .as_deref()
        .and_then(|username| username.strip_prefix(SA_USERNAME_PREFIX))
        .and_then(|rest| rest.split_once(':'))
        .ok_or_else(|| {
            DriverError::PermissionDenied(
                "sandbox credential is not a ServiceAccount token".to_string(),
            )
        })?;
    if service_account != expected_service_account {
        return Err(DriverError::PermissionDenied(
            "sandbox credential ServiceAccount is not accepted".to_string(),
        ));
    }
    Ok(Some(TokenIdentity {
        namespace: namespace.to_string(),
        pod_name: user_extra_one(user, POD_NAME_EXTRA)?,
        pod_uid: user_extra_one(user, POD_UID_EXTRA)?,
    }))
}
```

If `SA_TOKEN_AUDIENCE` is not already `pub` in `provisioner.rs:97`, widen it to `pub(crate)` and import it as `use crate::provisioner::SA_TOKEN_AUDIENCE;` instead of re-exporting. Do not duplicate the literal.

```rust
/// Reject a credential from a namespace this driver does not serve.
///
/// An empty `served` list means "not namespace-constrained" (cluster-wide
/// modes); binding is then carried entirely by `admit_owner`.
pub fn admit_namespace(namespace: &str, served: &[String]) -> Result<(), DriverError> {
    if served.is_empty() || served.iter().any(|candidate| candidate == namespace) {
        return Ok(());
    }
    Err(DriverError::PermissionDenied(
        "sandbox credential namespace is not served by this driver".to_string(),
    ))
}

/// Confirm the Sandbox CR resolved from a Pod's label really owns that Pod.
///
/// The Pod's sandbox-id label is caller-visible metadata and is not a trust
/// boundary on its own: it only becomes trustworthy once the CR it names agrees
/// that it owns that id *and* lives in the Pod's namespace. Without the second
/// check a Pod could name a sandbox in another namespace and borrow its
/// identity.
pub fn admit_owner(
    pod_namespace: &str,
    pod_sandbox_id: &str,
    cr_namespace: &str,
    cr_sandbox_id: Option<&str>,
) -> Result<(), DriverError> {
    if cr_namespace != pod_namespace {
        return Err(DriverError::PermissionDenied(
            "authenticated pod and its sandbox are in different namespaces".to_string(),
        ));
    }
    match cr_sandbox_id {
        Some(found) if found == pod_sandbox_id => Ok(()),
        _ => Err(DriverError::PermissionDenied(
            "authenticated pod is not owned by this sandbox".to_string(),
        )),
    }
}

/// A sandbox that disappears between authentication and lookup is a race a
/// client loses, not a server fault — report it as a rejection so it cannot be
/// mistaken for an outage.
#[must_use]
pub fn map_sandbox_lookup_error(error: DriverError) -> DriverError {
    match error {
        DriverError::NotFound(_) => DriverError::PermissionDenied(
            "sandbox for the authenticated pod no longer exists".to_string(),
        ),
        other => other,
    }
}

/// Map a failed TokenReview call onto a status an operator can act on.
///
/// A 403 here means this driver's ServiceAccount is missing the `tokenreviews`
/// create grant, which is a deployment fault. Reporting it as a rejected
/// credential would make a misconfigured install look like an attack.
#[must_use]
pub fn map_token_review_error(error: &kube::Error) -> DriverError {
    if let kube::Error::Api(response) = error {
        if response.code == 403 {
            return DriverError::Unavailable(
                "Kubernetes rejected the TokenReview call (403); the driver ServiceAccount \
                 needs create on tokenreviews"
                    .to_string(),
            );
        }
    }
    DriverError::Unavailable("Kubernetes TokenReview call failed".to_string())
}
```

```rust
    async fn authenticate_sandbox(
        &self,
        credential: &str,
    ) -> Result<(String, String), DriverError> {
        use crate::sandbox_auth::{
            admit_namespace, admit_owner, map_sandbox_lookup_error, map_token_review_error,
            reject_blank_credential, runtime_identity, token_review_identity,
        };
        use k8s_openapi::api::authentication::v1::{TokenReview, TokenReviewSpec};
        use k8s_openapi::api::core::v1::Pod;

        reject_blank_credential(credential)?;

        let reviews: Api<TokenReview> = Api::all(self.client.clone());
        let review = reviews
            .create(
                &PostParams::default(),
                &TokenReview {
                    metadata: ObjectMeta::default(),
                    spec: TokenReviewSpec {
                        audiences: Some(vec![SA_TOKEN_AUDIENCE.to_string()]),
                        token: Some(credential.to_string()),
                    },
                    status: None,
                },
            )
            .await
            .map_err(|error| {
                // Never log `credential`; it is secret-tagged in the proto.
                tracing::warn!(%error, "Kubernetes TokenReview call failed");
                map_token_review_error(&error)
            })?;

        let status = review.status.ok_or_else(|| {
            DriverError::Unavailable("TokenReview response had no status".to_string())
        })?;
        let identity = token_review_identity(&status, &self.cfg.sandbox_service_account)?
            .ok_or_else(|| {
                DriverError::Unauthenticated("sandbox credential was not accepted".to_string())
            })?;

        admit_namespace(&identity.namespace, self.served_namespaces())?;

        let pods: Api<Pod> = Api::namespaced(self.client.clone(), &identity.namespace);
        let pod = pods
            .get_opt(&identity.pod_name)
            .await?
            .ok_or_else(|| {
                DriverError::PermissionDenied("authenticated pod no longer exists".to_string())
            })?;

        if pod.metadata.uid.as_deref() != Some(identity.pod_uid.as_str()) {
            return Err(DriverError::PermissionDenied(
                "authenticated pod UID does not match the credential".to_string(),
            ));
        }

        let sandbox_id = pod
            .metadata
            .labels
            .as_ref()
            .and_then(|labels| labels.get(LABEL_SANDBOX_ID))
            .cloned()
            .ok_or_else(|| {
                DriverError::PermissionDenied(
                    "authenticated pod carries no sandbox id".to_string(),
                )
            })?;

        let (namespace, cr) = self
            .find_sandbox_cr(&sandbox_id)
            .await
            .map_err(map_sandbox_lookup_error)?;

        // The Pod's label named this CR; confirm the CR agrees it owns that id
        // and shares the Pod's namespace before trusting either.
        admit_owner(
            &identity.namespace,
            &sandbox_id,
            &namespace,
            cr.metadata
                .labels
                .as_ref()
                .and_then(|labels| labels.get(LABEL_SANDBOX_ID))
                .map(String::as_str),
        )?;

        let uid = cr.metadata.uid.as_deref().ok_or_else(|| {
            DriverError::FailedPrecondition("sandbox resource has no UID".to_string())
        })?;

        Ok((sandbox_id, runtime_identity(&namespace, uid)))
    }
```

```rust
use serde::Serialize;
use std::collections::BTreeMap;

#[derive(Serialize)]
struct ResourceAdmission<'a> {
    enabled: bool,
    required_labels: &'a BTreeMap<String, String>,
}

#[derive(Serialize)]
struct DriverAdmission<'a> {
    allow_driver_config: bool,
    resource_admission: ResourceAdmission<'a>,
}

/// Acknowledgement of the gateway's effective resource-admission policy.
///
/// The gateway builds the same policy from `[openshell.drivers.kyma]` and
/// rejects the driver at startup unless this string matches byte-for-byte, so
/// the wire format mirrors upstream's `DriverAdmissionConfig::acknowledgement`:
/// the literal `v1:` followed by the serialised policy. `BTreeMap` keeps key
/// order deterministic, which the equality check depends on.
#[must_use]
pub fn admission_acknowledgement(
    allow_driver_config: bool,
    admission_enabled: bool,
    required_labels: &BTreeMap<String, String>,
) -> String {
    let policy = DriverAdmission {
        allow_driver_config,
        resource_admission: ResourceAdmission {
            enabled: admission_enabled,
            required_labels,
        },
    };
    format!(
        "v1:{}",
        serde_json::to_string(&policy).expect("admission policy is plain data")
    )
}
```

- [ ] **Step 1: Write the script**

```bash
#!/usr/bin/env bash
# Render the chart's gateway TOML and prove the pinned upstream gateway
# accepts it. Config parsing happens before anything else in the binary, so a
# schema error is distinguishable from the unrelated runtime failures that
# follow when the image runs outside Kubernetes.
set -euo pipefail

CHART="deploy/helm/openshell-driver-kyma"
IMAGE="${GATEWAY_IMAGE:-ghcr.io/nvidia/openshell/gateway:latest}"
WORK="$(mktemp -d)"
trap 'rm -rf "$WORK"' EXIT

helm template check "$CHART" \
  --set gateway.sandboxJwt.enabled=true \
  --show-only templates/gateway-config.yaml > "$WORK/rendered.yaml"

python3 - "$WORK/rendered.yaml" "$WORK/gateway.toml" <<'PY'
import sys, yaml
doc = yaml.safe_load(open(sys.argv[1]))
open(sys.argv[2], "w").write(doc["data"]["gateway.toml"])
PY

echo "--- rendered gateway.toml ---"
cat "$WORK/gateway.toml"

out="$(docker run --rm -v "$WORK/gateway.toml:/etc/openshell/gateway.toml:ro" \
  --entrypoint openshell-gateway "$IMAGE" \
  --config /etc/openshell/gateway.toml --compute-driver kyma \
  --compute-driver-socket /run/openshell/driver.sock 2>&1 || true)"

if grep -qiE "failed to parse gateway config|unsupported gateway config version|unknown field" <<<"$out"; then
  echo "GATEWAY_CONFIG_REJECTED"
  echo "$out" | head -20
  exit 1
fi

echo "GATEWAY_CONFIG_ACCEPTED"
```

`mktemp -d` on macOS returns a path under `/var/folders`, which Docker Desktop does not share by default. If the script is ever run on a developer's Mac rather than CI, set `TMPDIR=$HOME/.cache` first; note that in a comment at the top of the script.
