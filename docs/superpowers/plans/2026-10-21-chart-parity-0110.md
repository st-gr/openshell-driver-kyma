# Upstream Chart Parity on Kyma (0.11.0) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the class (a) gaps between upstream OpenShell v0.1.4's Helm chart and ours, plus four defects, as chart release 0.11.0.

**Architecture:** The gateway TOML moves from a hand-written heredoc to a dict serialized by a port of upstream's `_toml.tpl`, so first-class values and the new `gatewayConfig` passthrough meet in one structure. Each gap is a value, a template change, a render assertion in a new `scripts/check-chart-parity.sh`, and (where it reaches a flag or TOML) an acceptance case in `scripts/check-gateway-config.sh`. cert-manager, Vault and SPIFFE are proven in a new kind smoke workflow; Gardener and the upgrade path live on `ods`.

**Tech Stack:** Helm 3 templates (sprig), bash, Python 3.12 via `uv` (PyYAML, `tomllib`), GitHub Actions, kind.

**Spec:** `docs/superpowers/specs/2026-10-21-chart-parity-0110-design.md`; appendix (upstream line references per gap): `docs/superpowers/specs/2026-10-21-chart-parity-0110-gap-audit.md`. Upstream sources: `git show v0.1.4:<path>` in a checkout of NVIDIA/OpenShell (chart under `deploy/helm/openshell/`).

## Global Constraints

- Chart: `deploy/helm/openshell-driver-kyma/` (abbreviated `CHART/` below). Version 0.11.0 for `Chart.yaml` `version`/`appVersion`, `Cargo.toml` and the two `Cargo.lock` entries (`openshell-bedrock-bridge`, `openshell-driver-kyma`).
- Gateway precedence: CLI flag > `OPENSHELL_*` env > TOML > default. Render each setting in exactly one place.
- No Rust changes. If one becomes necessary, `make test`, `make clippy`, `make fmt-check` in the dev container only.
- Telemetry: `gateway.telemetryEnabled` default `false` ("No telemetry to NVIDIA"); the driver stays without `openshell-core`'s `telemetry` feature.
- mTLS-only gateways accept sandbox client certificates as users (upstream's model); document it, no separate user CA.
- Existing values keep their names. New keys go under `gateway.*` / `gatewayService.*` / `rbac.*` / `serviceAccount.*` / `sandboxServiceAccount.*`; `gatewayConfig` is top-level.
- Upstream guard messages are copied verbatim, with upstream key names replaced by ours (`server.X` → `gateway.X`, `server.credentialDrivers` → `gateway.credentialDrivers`, `certManager` → `gateway.certManager`).
- Nothing is written to `istio-system`/`kyma-system`; no RequestAuthentication anywhere.
- Never write the cluster domain, tenant, client ids, emails or secrets into any file, commit, test fixture or log. Fixtures use `example.org`/`example.com`.
- Commits as `st-gr <38470677+st-gr@users.noreply.github.com>` (repo git config; no `-c user.email`); `git diff --cached` inspected before each commit; messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `check-chart-render.sh` (1680 lines) is not restructured; new assertions go in `scripts/check-chart-parity.sh`. Existing assertions that the changes legitimately alter are updated in place, each with a one-line comment naming the task.

## Review Focus

1. An existing install upgrading with unchanged values: the effective gateway TOML equals today's except the documented changes (`name`, telemetry env, `allow_unauthenticated_users` with a client CA). Pinned by Task 1's golden dicts, updated only by Tasks 3 and 6.
2. `gateway.extraArgs` containing a flag the chart now owns, in both `--flag=value` and `--flag value` forms, fails rendering with the replacement value named. Task 5 tests both forms.
3. A `gatewayConfig` table that a first-class value also writes (e.g. `openshell.gateway.otlp` plus `gateway.otlp.endpoint`): user keys win for non-owned keys and the table is emitted once. Task 2 tests it.
4. Gardener with `certificateDuration + certificateRenewBefore >= caDuration`, or with `certificateDuration < 2 × certificateRenewBefore` (Gardener's "at least twice the renewal window"): render fails before anything reaches the cluster. Task 16 tests both.
5. `networkPolicy.enabled=true` with Vault at `https://vault.example.org` (no port) opens 443, with `http://vault:8200` opens 8200; with `networkPolicy.enabled=false` no policy renders. Task 13 tests all three.
